# AginxOS 系统设计（2026-10-01；10-24 增补「三之二 能力积木」）

本页是系统设计真源——「数字世界里的人」世界观的第一文本。世界观看
这里；机上树细节见 `docs/FS.md`（2026-10-02 修宪换代：措辞已随本页，
树细节的唯一权威）；实验账 `docs/HARDWARE.md`；里程碑与裁决史
`AGENTS.md`。

## 一、是什么

AginxOS 是**黑匣子 ARM 服务器**（#422）：无屏、无本地语音、无摄像头；
人的参与止于刷机、通电、插网，此后一切操作归 agent（ssh / relay /
`agent://`）。

机器上跑的这个 agent 不是工具，是**这个人本身在数字世界里的存在**：

- **分身**——以「你」的身份在场：微信里说话的是你，电话里接打的是
  你，外网上活动的是你。对外不是一个 bot 在替人办事，是这个人数字
  化的本人。
- **助理**——以「为你」的姿态干活：办事、取材、记住事、定时提醒。

同一个实体，两个动词：**作为你**行动，**为了你**行动。

**没有母体**。「母体（总管）指挥编制（助理）」这层结构整个退役——
不是系统顶替母体的职位，是中枢指挥工人的世界观翻平。剩下的只有
一个**系统**：它是本体，不是管理员。

## 二、护城河：越用越懂你

人的数字活动分散在十个 SaaS bot 里，每个 bot 只看到人的一个碎片，
谁也不认识完整的你。这里所有对外动作都从这一台机器的几个门
（channels）出去，全部痕迹汇成**一条流**，落进**一份记忆**：

- 说话的方式、口吻、偏好——每个频道都留痕；
- 关系网：谁、怎么称呼、上次说到哪——联系人账本一等公民；
- 取材口味、决策习惯——晨报选了什么、外线怎么回。

**不可替换的资产是累积出来的「人的模型」**：记忆、关系、身份。
引擎（codex/grok）是雇来的劳动力，随时可换——这就是为什么从不
自研大脑：价值不在大脑（引擎商品化裁决，同日）。

## 三、五件套

| 构件 | 是什么 | 形态 |
|---|---|---|
| **系统** | 数字本人（本体）：对内是默认应答者，对外是门面。不是管理者 | `/home` 根人格 + gateway `system` 条目 |
| **能力面** | 这个人的**角色**：天气面、晨报面、斥候面——同一人格的侧面，不是员工名册 | `/home/workflows/<名>/AGENTS.md`=人格+规程；gateway 条目 `folder=` 即引擎工位 |
| **在场** | 这个人在各平台的**存在**：微信、relay（机器频道）、SIP（语音外线）……会有很多 | `/home/channels/<名>/` 数据 + `aginx-<名>` 包协议腿 |
| **人格真源** | 「你」的模型——唯一会增值的资产，跨频道跨能力面一份 | `/home` 记忆树（现 carrier.db，拆迁后独立成一等件） |
| **引擎** | 雇来的手：codex/grok/开源 CLI。商品、opt-in 包、可换 | 真身 `/var/bin` + `providers/<名>/` 壳 + 状态家 `/home/.<名>` |

派发面（真 aginx gateway + `agents/` 名册）是**机器结构**不是人格：
拉起引擎、记账、管权限，自己不思考。名册是唯一的引擎寻址处——
频道进来的消息按绑定路由到名册条目，引擎随条目换。

```
/home/
├── AGENTS.md             # 系统人格（定谳 2026-10-02；物理改名已收，刀④-1）
├── MEMORY.md  knowledge/ # 人格真源索引
├── channels/<名>/        # 在场（§四）
├── workflows/<名>/       # 能力面（AGENTS.md 即人格）
├── providers/<名>/       # 引擎人格壳（exec /var/bin 真身）
├── peers/                # 别人的 agent://
├── secret/               # 人的模型的钥匙层
└── run/                  # 工位（冷了可删）
```

## 三之二、能力积木：api + cli + 分身flow + channel（2026-10-24 立法）

**系统原则上只提供协议和执行的能力，其他一切可组合。**这是把
「系统自己长」从组织纪律升为架构原则：系统干活所需的每一样能力
都是**可下载、可组装、可热插拔的数据件**，而不是机身预置。

四类积木（能力四元组）：

| 积木 | 方向 | 是什么 | 形态 |
|---|---|---|---|
| **api** | 出（手） | 调外部服务的接口包装。腿=api 接口的声明包装——不是基建，是调用知识（URL 形状/参数/错误码）的外化。腿能装多少，系统的手就长多少 | TOML 声明（`[[tool]]`：url/params/extract/error_check/resolve/cron），凭据经 `auth_env`/账户选择器接入——多账户下 auth 是**选择器**（`account_kind` → 运行时解析到频道实例账户，见 §四）；duphub 分发，运行时注册即用（`api_tool_register`——agent 自己也能写） |
| **cli** | 内（本地执行） | 本地执行能力：工具（web-fetch/web-search）、复杂编排件、**引擎 provider（codex/grok 也是 CLI，D12 引擎不再例外）**。TOML 表达不了的多步编排降级为 CLI 件 | D13 `aginx-` 姓命令 / provider 裸名路由真身；pkg 分发（改机器的件） |
| **分身flow** | 知（剧本） | 怎么把事做成的组合知识：人格+规程+流程+知识库。编排 api 与 cli 成事的是它 | `/home/workflows/<名>/`（AGENTS.md+flows+knowledge）；duphub 分发（改变人的件） |
| **channel** | 入（门） | 在场：外部世界主动来找系统。收消息→路由能力面→回话。协议腿（门）本身也是可下载工件——iLink 是第一个，将来的门都从市场来 | `aginx-channels` 骨架（daemon+注册表+契约）+ 频道腿工件；`channels/<名>/` 实例目录由系统落 |

对偶：**api=出，channel=入，cli=本地跑，flow=剧本**。一条消息的完整
生命：channel 进 → 路由能力面 → flow 指挥 api/cli 干活 → 产物落盘或
经 channel 出去。

积木的**分发分工**（供应链不在四元组内，是它的进货渠道）：

```
duphub.com（dup）    改变【系统=这个人】的件：分身、api 腿、频道门腿
                      ——市场节奏，系统自己拉，热插拔，删目录即拔
pkgs.aginx.net(pkg)  改变【机器】的件：机身二进制、服务单元、引擎真身
                      ——平台发版节奏，签名 manifest
```

四元组下面还有一层**机身基建**（L0、pkg 体系、relay、channels daemon
骨架、腿的接口契约）——积木运行的底盘，平台维护，系统侧不感知。

**已被替代的路径**：MCP server 模式被声明式 api 工具取代（MCP 只在
「独立进程、多语言集成」的边缘场景共存）；腿不做进 channels 主包
（主包永远只是骨架+契约，不随频道数量膨胀——新平台=上架新腿，
零发版零升机）。

**系统自动添加**（「用户只丢凭据和一句话，剩下全是系统的」）：
装分身=读依赖声明→从 duphub 拉腿→落频道实例目录（文件夹即注册表）→
凭据入密（secretd 持本体、频道实例目录持引用，见 §四；不进 TOML 不进
repo）→token 验活→回执。每个环节都是系统的纯数据行为，零装配零代劳。

**能力自动生成**（铸造链，10-24 同日立法）：四类积木全是数据件
（TOML/markdown 文本），铸造积木=文本工作=agent 本职。用户丢一个
API 文档（或 URL），系统即可：读文档（cli）→ 铸腿（提取接口生成
`[[tool]]` 声明，落盘注册立即可用）→ 验活（真调一发，验收=验效果
非语法）→ 铸分身（clone-creator 造能力面：AGENTS.md+flows 编排新腿）
→ 试跑回执 →（可选）dup push 上架复用。零编译零部署零平台参与；
写操作类接口（publish/删除/扣费）的 admin 门分级在铸造时就带上。
机制先例：opencarrier `api_tool_register`（definition 传 TOML 写入即用）。

**探索先行**（无现成件时，research 前置）：用户只丢一个需求（「接管
这个公众号」——无腿无分身无文档），由 **aginx-research 探索**：搜官方
文档、抓平台能力、只读试调，产出两件交接工件——**api 接口文档汇编
+ 分身规划**（要做什么、风险表）；铸造链以此为输入接手（文档→腿，
规划→分身），完成接管。分工：research=面对未知的探索（长知识），
铸造链=面对已知的生产（长积木），duphub=已铸件的复用缓存——第二台
机器遇到同一 API 直接拉，不重铸。

**权限分级随腿走**：draft/publish 分离——建草稿开放给能力面，真发布
过 admin 门（人审）。AI 内容只进草稿箱，人审后手动发，纪律内建于
工件契约。

## 四、channels——在场（本日新立）

频道是一等公民、可插拔、会有很多个。ilink（微信）是第一个；relay
是机器频道；SIP/PSTN 是语音外线频道；telegram/email/webhook 皆可能
来。relay 与 SIP **现役不动**——只是在世界观里归位为频道，不是重构
命令。

```
/home/channels/<名>/
├── channel.toml          # 类型 + 默认绑定 + 策略（DM/群组/限流/格式）
└── accounts/<稳定键>/     # 多账户=同频道多实例（2026-10-24 定形）
    ├── account.toml      # 非敏感元数据（昵称/号类型/默认绑定）；secret 引用→secretd
    └── senders/<uid>/    # 该账户的会话状态；绑哪个能力面是记录里的字段
```

- **多账户=同频道多实例**（2026-10-24 定形，公众号第一走通）���`accounts/<稳定键>/`
  一户一目录，**键不可自选**（公众号=appid、iLink 将来=wxid），人起的名只是
  account.toml 里的昵称——改名不搬家、重名不冲突。**凭据本体住 secretd**
  （键=`频道:稳定键`——backup 排除 secret store 的纪律自然覆盖；每户独立
  验活，失效回执「请重投」不静默），实例目录只放引用+元数据，删目录=删
  引用、孤儿键走检测清。env 单键=单账户假设，撞墙即迁。多机各存各账
  （跨机搬运零回显），IP 白名单=接手回执必带检查项。iLink 现役不动，
  走通再推广。

- **一频道 = 一目录 + 一包**：协议腿住 opt-in 包（`aginx-channels`
  唯一机身，#69 改形），目录只有数据和绑定。装频道=落目录+opt-in，
  裸 L0 零频道。
- **文件夹即注册表**——与 workflows/ 同律（注册表=文件系统的延续）。
- **绑定以频道为轴**：会话住 `channels/<名>/senders/<uid>/`，换绑=
  改字段，不再搬家（翻转 carrier 的以分身为轴、重绑搬家的旧律）。
- **频道不感知引擎**：桥只认「把文本交给某 agent、拿回文本」窄接口，
  按 channel.toml 路由到 gateway 名册。

通道层设计已有两个参照（carrier 现役实现 + openfang 40 频道），同
血统，不用发明：

- **继承 carrier 的**：一频道一 crate 纪律（升格为一频道一包）；
  绑定即路由的简单性（openfang 五层优先级路由对我是过度设计——没有
  群组/多租户场景）；出站三课（送达是关系账本 best-effort、
  proactive push 探测、last-channel 积压 drain）；逐 sender 串行
  （微信重投不双答）；频道自带工具。
- **从 openfang 引的**：频道声明式配置（channel.toml≈其
  ChannelOverrides：策略不进码）；文件夹即注册表（落目录即装频道）。
- **两边都不要的**：slash 命令面在桥层截胡（对账走 agc/ssh，人面
  消息直达能力面）；typing/emoji 表演（黑匣子无人看）。

## 五、机身

L0 底座不变（2026-09-12）：kernel+init+supervisor+network+ssh+pkg，
svc.d 恰 2 单元，其余全是 opt-in 包——引擎、频道、工具皆包。机器是
数据（D14）：`devices/<codename>/`，server-class 板卡一等机器，
boot 面以上原样复用。D13 姓氏法、升级四通道、密钥纪律、模型与大件
不进 state tar 全沿用。细节真源：`AGENTS.md`、`devices/README.md`、
`rootfs/README.md`。
