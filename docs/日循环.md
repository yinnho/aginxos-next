# 日循环线（daily-review）——最小闭环设计 v0

状态：已裁决开工（2026-10-10）。上位法：`docs/DESIGN.md`（memory=人格真源，
越用越懂你=护城河）。本线是那句「越用越懂」的**发动机**：系统每晚自己
整理当天做了什么、查缺、补漏，缺口喂给次日晨报。

核心原则：**lifecycle 保持零 LLM 依赖的设计不动**——prompt 它出、JSON
它解析、知识它落账；中间的「想」一跳交给引擎（codex，D12 商品劳力）。
这正好是晨报线已验证的三段式，复用不发明。

## 一、三段式（仿晨报 codex 化）

```
47 23 * * *  day-review.sh（aginx-mem 包 [cron] 行，避整点）
 │
 ├─ Leg A 确定性收集：aginx-mem day --date 今日
 │    材料化当天输入（见二），stdout 出 JSON：
 │    { sources: [...], known_index: [...], output_contract: "..." }
 │
 ├─ Leg B codex 一回合：
 │    prompt = lifecycle::evolution::build_analysis_prompt()   ← 原核
 │            + 日批包一层（known_index + sources 摘要）
 │    codex exec --budget 900s → 原样 JSON
 │
 └─ Leg C 确定性落账：aginx-mem digest --workspace <system>
      parse_analysis_response() → apply_evolution()
      ├─ knowledge 落 knowledge/*.md（frontmatter+双层格式）
      ├─ MEMORY.md 索引重建（引用断=health 当场逮）
      ├─ version JSONL 留痕（今天谁改了什么）
      └─ gaps + k lint 摘要 + evaluate 覆盖度
         → /home/workflows/morning-report/inputs/day-review.md
```

**gaps 字段不用发明**——evolution 的提示词原生就有
`"gaps": ["发现的知识缺口"]`，查缺的出口本来就在图纸上，只是从没通电。

## 二、day 材料清单（Leg A 的输入面）

| 源 | 路径（redfin 实测） | 供给什么 |
|---|---|---|
| 对话正文（真源，FS.md） | `/root/.codex/sessions/<Y>/<M>/<D>/*.jsonl`（~136KB/天量级） | 当天全部回合原文——evolution 的消化对象 |
| 会话索引 | `/var/lib/aginx/gateway{,-local}/sessions.json` | 谁在说话、题目、回合数（正文太长时的分诊层） |
| 晨报执行账 | `/home/workflows/morning-report/logs/codex-*.log` | 例程有没有真跑、降级没降级 |
| 研究实例账 | `/home/research/*/`（status 子命令/v0.1.2） | 各实例当日回合数、队列、产出落库 |
| 频道收发 | channels 日志/投递记录 | 微信面当天进出 |
| 已知索引 | `aginx-mem k ls` | prompt 判断标准第 4 条（「已存在于索引中的不提取」）的对账面 |

运行面体检（load/mem/盘/备份件）**不并入**——collect.sh 已有、晨报已在
用，日循环只管知识面+活动对账，不重复造。

## 三、落账与消费

- **知识落点**：`/home/knowledge/`（系统=人格本体，工作区根就是
  /home——AGENTS.md/MEMORY.md/knowledge/ 同级，④-5 布局）。private
  scope 走 evolution 原有的 sender-data-dir 分流，不进公库。
- **缺口消费**：day-review.md 是晨报的输入件——08:00 晨报卡从「播新闻」
  升格出「昨日自查」段：新学 N 条 / 陈了 M 条 / 缺口清单 / 修不了的
  上报用户。
- **降级纪律**：codex 超时/坏 JSON → 缺口清单照落（标 degraded），空跑
  日（无活动）幂等零产出，绝不静默也绝不炸。

## 四、包形态与 CLI 面

- **归属**：`aginx-mem` 升 v0.2.0 带上 `[cron]` 行——工具同一真身，不
  新开包（#472 A 正典：例程归包，禁手拷）。
- **wrapper**：`pkgs/aginx-mem/files/libexec/day-review.sh`，仿
  morning-codex.sh（预算、超时、产物验收**核内容不听汇报**）。
- **新子命令两个**（本仓 Rust 改动面，其余全是接线）：
  - `aginx-mem day [--date YYYY-MM-DD]` — 材料化（只读）
  - `aginx-mem digest --workspace <dir>` — stdin 吃 codex JSON，
    落 knowledge+版本+索引+缺口件（写）

## 五、验收门（最小闭环 done 的判据）

1. 手触发一次：knowledge/ 长出 ≥1 件带 frontmatter，version JSONL 有
   当天行，MEMORY.md 引用全通（k lint 0 error）。
2. 次日晨报卡含「昨日自查」段——**真人眼验**，不是日志说有。
3. 空跑日幂等：无活动 → 零新文件、零报错。
4. 坏 JSON 注入测试：digest 拒收且缺口件标 degraded。

## 六、第一刀不做（后批）

- **bloat 两段过期**（知识会烂：30天陈→expired→60天删）——第一批只
  把 gaps 报出来，清理纪律等知识库先长起来。
- **compile/watcher 环**（knowledge→system prompt 活编译）——人格是
  活的终局形态，等日循环稳定供血后再通。
- **feedback 匿名回传**（模板线附属，随用随接）。

## 七、风险与边界

- sessions jsonl 可能含敏感上下文：Leg B 走设备本地 codex→brain，不出
  机；private 分流已有。**绝不把 day 材料拷出设备**（备份排除面同律）。
- 知识质量闸：digest 前置 k lint，坏件当场 heal（health 695 行已备）。
- 体量：当前对话量 ~百 KB/天，一回合 codex 足够；将来超限再上分诊
  （sessions.json 索引先分诊、长会话摘要后入 prompt）。
